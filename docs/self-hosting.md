# 自分でアプリを動かす

Nostr-Rating のアプリは誰でも自分の GitHub アカウントで動かせます。公開リポジトリの GitHub Pages と GitHub Actions は無料で使えるので、費用はかかりません。

自分で動かしたアプリも、設定を変えなければ同じ公開リレーを使います。そのため、ほかの URL で遊んでいる人ともそのまま対戦できます。

## 必要なもの

- GitHub のアカウント
- ブラウザ（手元にプログラムを入れる必要はありません）

## 手順

### 1. リポジトリを fork する

元のリポジトリのページで「Fork」を押し、自分のアカウントにコピーを作ります。リポジトリ名は変えてもかまいません。アプリの URL は `https://<アカウント名>.github.io/<リポジトリ名>/` になります。リポジトリ名を `<アカウント名>.github.io` にした場合は、`https://<アカウント名>.github.io/` になります。

### 2. GitHub Actions を有効にする

fork したリポジトリでは、GitHub Actions が止まった状態で始まります。リポジトリの「Actions」タブを開き、有効にするボタンを押します。

### 3. GitHub Pages の配信元を選ぶ

「Settings」→「Pages」を開き、「Build and deployment」の「Source」で「GitHub Actions」を選びます。

### 4. アプリを配信する

「Actions」タブで「Deploy to GitHub Pages」を選び、「Run workflow」を押します。数分で終わり、手順1の URL でアプリが開けるようになります。

以後は `main` ブランチに push するたびに配信し直されます。

### 5. スナップショットの定期実行を始める

「Actions」タブで「Snapshot」を選び、「Run workflow」を一度押します。以後は毎日 5:00（日本時間）に、締め切りを迎えた対戦をゲームごとに集計します。スナップショットの部品をリリースに上げ、目次を `snapshots/<ゲーム>/` に積んでから、GitHub Pages を配信し直します。アプリは自分の Pages からスナップショットを読みます。スナップショットがまだ無い間は、今のシーズンの最初から計算します。

部品のリリース（`snapshot-<ゲーム>-…`）は、ゲームごとに毎日1つずつ増えます。消すと、そのリリースを指しているスナップショットの続きを作れなくなるので、消さないでください。リポジトリは公開のままにしてください。非公開にすると、Actions がリリースから前回の部品を取れなくなります。

GitHub は60日間動きのないリポジトリの定期実行を止めます。止まったときは、「Actions」タブの「Snapshot」から再び有効にしてください。

### 6. 復活の道具をリリースする

「Actions」タブで「Recovery tool」を選び、「Run workflow」を押します。タグ（例: `recovery-v1`）を入れると、復活の道具（`nostr-rating-recovery.html`）をビルドしてリリースに添付します。リリースを出すと GitHub Pages も作り直され、アプリとヘルプの入手先のリンクが、一番新しい復活の道具のリリースを指すようになります。復活の道具のリリースは「最新」（Latest）にしないので、アプリなどほかのリリースは今までどおり出せます。

復活の道具は普段のアプリとは別の場所で開くためのファイルです。GitHub Pages には載せないでください。

## 気をつけること

### ほかの人と対戦するには設定を変えない

`configs/relays.json`（リレーの一覧）とゲームの定義（`configs/games.json` にあるゲームの `configs/<ゲーム>.json`）を変えると、ほかの URL で遊んでいる人と対戦できなくなったり、レートの計算が合わなくなったりします。自分だけのルールで遊びたいときを除き、そのままにしてください。

### 同じアカウントのほかの Pages と同居する

`<アカウント名>.github.io` の下にあるページは、ブラウザから見るとすべて同じ場所（origin）です。アプリの端末の鍵はこの場所ごとにしまわれます。同じアカウントで、中身を確かめていないページを公開しないでください。そのページから鍵を使われるおそれがあります。気になるときは、このアプリ専用の GitHub アカウントを作るか、独自のドメインを設定してください。

### 元のリポジトリの変更を取り込むとき

fork したリポジトリには、元のリポジトリの変更は自動では入りません。GitHub の「Sync fork」で取り込めますが、取り込む前に変更の中身を確かめてください。自分の URL で配るコードを決めるのは、あなた自身です。

### アカウント名を変えたり、アカウントを消したりするとき

アカウント名を変えると、アプリの URL も変わります。古い URL にしまった端末の鍵は使えなくなるので、変える前に新しい URL を端末として登録してください（ヘルプの「運営やアプリの URL が変わったとき」と同じ手順です）。アカウントを消した場合、その名前を別の人が取ると、古い URL のページを別の人が配れるようになります。使っていた端末は取り消しておいてください。
