# 0008. アカウントを鍵の出来事の記録（KEL）で表す

- 状態: 採用（2026-10-28）

## 背景

これまでは、1つの Nostr の秘密鍵がそのままアカウントだった。秘密鍵はアプリの中（`localStorage`）か NIP-07 の拡張機能にあり、次の2つの問題があった。

- 同じ origin で悪いコードが動くと、秘密鍵を持ち出される。
- Nostr の鍵は取り消せないので、一度盗まれると被害がいつまでも続く。

同じ origin の悪いコードに、ページが開いている間に鍵を使われることは、どの方式でも防げない。防げるのは鍵の持ち出しと、被害が続くことの2つで、この設計はこの2つに絞って守る。安全の拠り所を、特定のドメインや運営には置かない。

利用者向けの説明は `apps/web/public/help/account.html`（アプリの「ヘルプ」）にあり、この ADR はその説明を実現するための決定である。

## 決定

KERI（Key Event Receipt Infrastructure）の考え方を借り、Nostr のイベントの上に小さく作り直す。KERI の実装（CESR、証人、KAWA）は取り込まない。0001 のうち「本人性は NIP-39 で示す」と、鍵を1つだけ持つ前提を、この ADR で置き換える。

### 鍵の役割

| 鍵 | 利用者向けの呼び方 | 持ち方 | できること |
|---|---|---|---|
| 次の鍵 | 復活の言葉 | 12語（BIP-39）から NIP-06 で作る secp256k1。紙に書いて保管する | 入れ替え（rot）にだけ一度使う |
| 端末の鍵 | 端末の鍵 | WebCrypto の ECDSA P-256（`extractable: false`）か、NIP-07 の署名アプリ | 証明書を出す。端末の追加・取り消し・延長 |
| 掲載用の鍵 | （出さない） | 端末ごとの secp256k1。アプリ内に置く | KEL のイベントを Nostr に載せる。権限は持たない |
| 使い捨ての鍵 | 使い捨ての鍵 | 端末ごと・1日ごとの secp256k1 | 募集・申し込み・対戦・報告・紐づけに署名する |

次の鍵は作成の宣言と入れ替えに公開鍵のまま載せる。KERI はハッシュで隠すが、この用途では入れ替えのイベントを `authors` で探せることを優先する。しきい値は 1-of-1 を既定とし、2-of-3 も選べる。

### 記録（KEL）

- 新しいイベントの種類として kind 3753（鍵の出来事）を使う。0001 で引き継ぎ用に予約していた番号である。
- 中身は `icp`（作成の宣言）、`ixn`（端末の追加・取り消し・延長）、`rot`（入れ替え）の3種類で、番号 `sn` と直前のイベントの id（`prior`）でつなぐ。
- アカウントの識別子（以下 aid）は、`icp` の本文の SHA-256 とする。
- 本文への署名は Nostr のイベントの署名とは別に持つ。`icp` は載せた全端末、`ixn` は有効な端末1つ、`rot` は次の鍵のしきい値分が署名する。
- Nostr のイベントとして載せるのは、`icp` と `ixn` は端末の掲載用の鍵、`rot` は次の鍵そのもの（NIP-06 の鍵）である。

### 上書きの規則

KERI の規則をそのまま使う。

- 同じ番号では、`rot` が `ixn` を上書きできる。
- `rot` は別の `rot` を上書きできない。
- `ixn` は何も上書きできない。
- 次の鍵を空にした `rot` はアカウントの放棄とする。

同じ番号に上書きできないイベントが2つあるときは、先に見たほうを正とする。全員が同じ結果を出すため、「先に見た」はスナップショットが最初に記録した版とする（下の「時計」）。

### 端末の期限

端末の登録には期限を付ける。既定は 90 日とし、アプリは期限まで 30 日を切った端末を `ixn` で自動的に延長する。使われなくなった URL の端末は取り消さなくても切れる。

### 使い捨ての鍵と証明書

- 端末は1日ごとに使い捨ての鍵を作り、端末の鍵で証明書を出す。証明書には aid、端末の id、使い捨ての公開鍵、KEL の先端の id、有効期間（開始から 24 時間）を入れる。
- アプリのイベントは使い捨ての鍵で署名し、証明書をタグで持ち歩く。
- 証明書が有効なのは、出した端末が開始の時点で有効で、その端末を取り消すイベントより前に開始したときだけである。取り消したあとも、取り消し前に出した証明書は期限まで残る。利用者向けの説明の「最大でおよそ1日分」は、この期間を指す。

### 外部アカウントの紐づけ

NIP-39（kind 10011）は使わず、アプリ独自のイベントで aid と X・GitHub の投稿を結ぶ。投稿する文には npub ではなく aid を入れる。X は oEmbed（認証なし）で投稿者と本文を確かめる。Mastodon はやめる。

### 時計

`created_at` は本人が決められる値なので信用しない。スナップショットは前回の締め切りから締め切りの幅（24 時間）を引いた時刻より古いイベントを受け付けない。そのため、日付を遡らせたイベントが効くのは、この幅の中だけである。KEL のイベントも、スナップショットが最初に記録したものを全員の最初の版とする。

アプリと復活の道具は、今より10分を超えて先の日時の KEL のイベントを使わない。盗まれた端末で先の日時のイベントを出しておくと、その上に続けた取り消しや `rot` の日時も先になり、スナップショットはその日時まで受け付けない。こうして取り消しと復活を遅らせる攻撃を防ぐ。

### 検索をあふれさせる攻撃

- 取り切る必要がある問い合わせは、`authors` か `ids` だけにする。
- あふれさせられるのはその鍵の持ち主だけにし、取り切れないときは、その回はそのアカウントの報告と公開情報を使わない。そのアカウントの対戦は相手の報告に合わせて確定する。全体は止めない。
- `#t` の問い合わせは新しいアカウントを見つけるきっかけにだけ使い、取りこぼしを許す。

### 復活の道具

復活の言葉は普段のアプリとは別の origin でだけ入力する。そのために、復活の道具を HTML 1ファイルにまとめ、リポジトリのリリースに添付する。利用者はダウンロードして開く（`file://`）。新しい端末が表示する「端末の申請」を道具に貼ると、道具が `rot` を作ってリレーに載せる。同じ処理を CLI からも呼べるようにする。

道具の `rot` は最後の `icp` か `rot` の次に置き、そのあとの `ixn` をすべて上書きする。盗まれた端末で同じ番号の別の `ixn` を出されていても、スナップショットを含め、どちらを先に見た人にも同じ `rot` が通る。上書きした `ixn` で足した端末のイベントは、だれのものでもなくなる。

### これまでの形との関係

アプリはまだ公開していないので、移行の仕組みは作らない。アプリ内の秘密鍵の方式はやめ、既存のスナップショットは作り直す。

## 影響

- 鍵を持ち出されても、アカウントを復元できる。復活の言葉を盗まれない限り、アカウントを取り上げられることはない。
- ほかの Nostr クライアントからは使い捨ての鍵ごとに別人に見える。プロフィールと紐づけは、このアプリの中でだけ通じる。
- 端末を追加するたび、また 60 日ほどごとに、KEL のイベントが1つ増える。
- 「先に見た版」を決めるのはスナップショットを作る人で、ここは中央に寄った部分として残る。誰でも作り直して確かめ、置き換えられる。
- 実装は重くなる。KEL の評価、上書き、期限、保留を、アプリと CLI が同じ結果になるよう `packages/core` に1つだけ書く。
