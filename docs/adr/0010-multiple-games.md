# 0010. 複数のゲームを1つのアプリで扱う

- 状態: 一部置き換え（0013）

## 背景

最初の仕様ではゲームの定義を足せるようにし、利用者がアプリでゲームを選んで参加する想定だった。PoC では1ゲーム（スマブラSP）だけを動かしたので、次の部分が1ゲームを前提にしたまま残っている。

- アプリは定義ファイルを1つだけ読み込み、ゲームを選ぶ画面がない。
- スナップショットと公開 API の置き場所に、ゲームの区別がない。
- アカウントの公開情報（表示名と紐づけ）が、ゲームごとのイベントになっている。
- 定義の形と結果の報告が格闘ゲームを前提にしている。キャラ・ステージ・ストック・部屋 ID が必須で、引き分けがない。

1ゲームだけだと、こうした前提に気づかないまま広がる。そこで、性質の違う2つ目のゲームとしてチェスの定義を足し、両方が同じ仕組みで動くことを確かめる。

## 決定

### アプリでゲームを選ぶ

- アプリは `configs/games.json`（定義ファイルの一覧）にあるゲームをすべて同梱し、利用者が選ぶ。最後に選んだゲームを覚える。
- アカウント（KEL、端末、復活の言葉、使い捨ての鍵）は全ゲームで共通にする。
- レート、対戦設定、マッチング、ランキング、シーズンは、ゲームごとに分ける。

### 定義の形

定義を、どのゲームにもある部分と、ゲームによって使う部品に分ける。

| 部分 | 中身 | スマブラSP | チェス |
|---|---|---|---|
| 共通 | `id`、`name`、`rating`、`rematchWeight`、`matching`、`report`、`seasons` | あり | あり |
| `format` | 何本先取か（`bestOf`）と、対戦ルームに出す説明（`notes`） | 2本先取 | 1局 |
| `results` | 報告できる結果。`win`・`lose`・`cancel` は必ずあり、`draw` は選べる | 引き分けなし | 引き分けあり |
| `characters` | キャラの一覧と、拒否ステージを共有する組 | あり | なし |
| `stages` | ステージと、拒否の決まり | あり | なし |
| `sides` | 先後（P1・P2、白・黒など）の名前。対戦ごとにどちらがどちらかを決める。1つ目の側が対戦の場所を用意する | P1・P2 | 白・黒 |
| `room` | 対戦の場所の受け渡し。部屋 ID とパスワード（`code`）か、招待リンク（`link`） | 部屋 ID | 招待リンク |

- プロトコルのイベントの `firstFighter`、`p1Fighter`、`p2Fighter` は、`characters` があるゲームでだけ使う。ないゲームでは空にする。
- 先後はマッチ成立のイベントの id から決める（id の最後の16進数が偶数なら p1 が1つ目の側）。どちらのクライアントも同じ結果を出せ、募集した側が選ぶこともできない。すべてのゲームで使い、スマブラSP でも部屋を立てる人（P1）をこれで決める。これまでの「先に待っていた人が部屋を立てる」はやめる。
- 招待リンクは `https://` で始まるものだけを受け付ける。対戦相手から届くリンクなので、アプリはリンク先の名前（ホスト名）を見せてから開く。

### 引き分け

- 結果報告に `draw` を足す。双方が `draw` を報告したら、引き分けで確定する。一方の `draw` と他方の `win`・`lose` は噛み合わない（食い違い）。
- 引き分けは Glicko-2 で 0.5 として計算する。勝ち数と負け数のほかに、引き分けの数も数える。
- `results` に `draw` がないゲームでは、`draw` の報告を無視する。

### スナップショットと公開 API

- スナップショットは `snapshots/<game>/season_<N>/…` に置き、`snapshots/<game>/latest.json` がそのゲームの最新を指す。毎日のワークフローは一覧のすべてのゲームの分を作る。
- KEL はゲームに依存しないが、各ゲームのスナップショットがそれぞれ記録する（ゲームごとに独立して作り直せるように）。
- 公開 API は `api/v1/<game>/…` に置く。選手ページ（`p/<aid>.html`）は1人1ページとし、ゲームごとのレートを並べる。

### アカウントの公開情報

- アカウントの公開情報（kind 30756）から `game` タグを外し、全ゲームで共通にする。

### チェスの定義

- 1局で勝敗を決める。持ち時間は、国際チェス連盟（FIDE）の世界ラピッド選手権と同じ15分＋10秒とし、定義の `format.notes` に書く。
- 対局は、双方が使えるオンラインの対局サービスで行う。先手（白）の人が招待リンクを作って送る。どのサービスを使うかはアプリでは決めない。

### これまでの形との関係

アプリはまだ公開していないので、移行の仕組みは作らない。スナップショットと公開 API の置き場所は、この形で作り直す。

## 影響

- ゲームを足すには、定義ファイルを書いて `configs/games.json` に足すだけでよい。ただし、`characters`・`stages`・`sides`・`room` の部品で表せないルールのゲームは、コードを直す必要がある。
- 1つのアカウントで、すべてのゲームに参加できる。紐づけも1回で済む。
- プロトコルのイベントの形が変わる（`results` の `draw`、空のキャラ欄、アカウントの公開情報のタグ）。
