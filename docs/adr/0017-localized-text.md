# 0017. 表示の文字列を言語ごとに持つ

- 状態: 採用（2026-11-04）
- 0010 の「定義の形」に、表示の文字列の形を足す。

## 背景

アプリ、文書、定義ファイルは日本語だけで書いてきた。スマブラSP の利用者は日本語話者が中心なので困らなかったが、チェスのように日本語話者に限らないゲームを足すと、画面を英語でも出す必要がある。

ゲームの定義ファイルには、ゲーム名、キャラやステージの名前、先後の名前、対戦ルームに出す注意書きが、日本語の文字列として入っていた。

## 決定

- 定義ファイルの表示の文字列（`name`、`format.notes`、`sides`、`characters.list[].name`、`stages.all[].name`、`room.entryRestriction`、`room.notes`）は、文字列か、言語ごとの文字列を持つオブジェクト（`{"ja": "…", "en": "…"}`）で書く。文字列はどの言語でも同じ表記（`P1` など）として扱う。オブジェクトはアプリが扱うすべての言語（`packages/core/src/game/text.ts` の `LOCALES`）を持たなければならない。
- イベント、スナップショット、レート計算の設定値のハッシュには、表示の文字列を入れない。入れるのは `id` や先後の番号のような、言語によらない値だけにする。表示するときに、表示の文字列の言語を選ぶ。
- 画面の文言は使う部品のそばに `messages({ ja, en })` でまとめて置く。片方の言語だけを足すと型検査が通らない。
- 公開 API の `game` にはこれまでの `name`（日本語）を残し、言語ごとの名前を `names` として足す。
- 画面の言語は選んだ言語、ブラウザの言語の順で決め、どちらでもなければ英語にする。
- 文書は日本語を正とする。英語版は翻訳として、元にしたコミットを冒頭に書く。

## 影響

- 言語を足すには、`LOCALES` に足し、定義ファイルとすべての `messages` にその言語の文字列を足す。どれかが欠けると、定義ファイルの読み込みか型検査で止まる。
- 表示の文字列はレート計算の設定値のハッシュに入らないので、変えてもシーズンの途中でスナップショットの生成は止まらない。
- 紐づけの検証用の文（`Verifying my Nostr-Rating account: <aid>`）は、もともと言語によらない固定の文なので変えない。
- 表示の文字列を言語ごとに分けずに書いた定義ファイルも、そのまま読める。その文字列はどの言語でも同じ表記として表示する。
