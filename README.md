# Nostr-Rating

運営のいない、1対1の対戦ゲームのレート戦です。
対戦の募集、結果の報告、レートの計算を、中央サーバーなしで [Nostr](https://github.com/nostr-protocol/nips) の上で行います。

ゲームごとのルール（キャラ、ステージ、試合の形式、報告の締め切り、レートの値など）は、定義ファイル（`configs/<ゲーム>.json`）にまとめています。
今は大乱闘スマッシュブラザーズ SPECIAL の定義（[`configs/smash_sp.json`](configs/smash_sp.json)）が入っています。

> **状態:** 開発中です。仕様や保存形式は予告なく変わることがあります。

## なぜ作ったか

スマブラSP 向けの非公式レート戦サイト「スマメイト」は、2026年10月25日に閉鎖されました。
運営がいなくなると、サービスは続けられません。

Nostr-Rating は次の2つの考え方で、運営に依存しないレート戦を作ります。

1. **情報を守ろうとしないことで、安全性を保証する。**
   守るべき個人情報も、秘密のデータベースも持ちません。対戦結果はすべて本人の署名付きで公開され、誰でも検証できます。
2. **運営がいなくても続く。**
   仕組みだけで回るので、特定の人やサーバーがいなくなっても止まりません。メンテナが入れ替わっても続けられるよう、コードと手順をすべて公開しています。

## 仕組み

```
 ┌────────────── ブラウザ（GitHub Pages から配信）──────────────┐
 │ Web アプリ（React）                                          │
 │   ・鍵: 端末の鍵（WebCrypto）と毎日の使い捨ての鍵            │
 │   ・手元のキャッシュ: SQLite（OPFS）                          │
 │   ・レート計算: packages/core（スナップショット + 差分）      │
 └──────────┬───────────────────────────────┬──────────────────┘
            │ WebSocket（複数リレーに同時接続） │ HTTPS
   ┌────────▼────────┐               ┌─────────▼───────────────────┐
   │ 公開 Nostr リレー │               │ GitHub リポジトリ             │
   │（configs/relays.json）│          │  configs/relays.json         │
   └────────▲────────┘               │  configs/smash_sp.json       │
            │                         │  snapshots/                  │
   ┌────────┴────────────────────────┐ └─────────▲───────────────────┘
   │ スナップショット生成（Actions で毎日）│──────────┘
   └─────────────────────────────────┘
 復活の道具（HTML 1ファイル）: リリースからダウンロードし、普段のアプリとは別の場所で開く
```

### データの流れ

1. **アカウント:** アカウントは1つの鍵ではなく、鍵の出来事の記録（KEL）で表します。端末の鍵は取り出せない形で端末にしまい、
   毎日の使い捨ての鍵に証明書を出します。端末を失くしたり盗まれたりしても、紙に書いた「復活の言葉」で取り返せます
   （[ADR 0008](docs/adr/0008-key-event-log.md)、利用者向けの説明はアプリの「ヘルプ」）。
2. **紐づけ:** アプリが「このアカウントは私のものです」という文を表示し、プレイヤーはそれを X に投稿するか GitHub の Gist に貼ります。
   どちらも自動で確認します。1人で何個もアカウントを作れないようにするためのものです。
3. **募集と申し込み:** 「対戦相手を探す」を押すと、条件に合う募集に申し込むか、自分が募集を出します。
   条件はレート差・連戦・マナーの目安の3つで、どれも双方のクライアントがそれぞれ判定します。
4. **マッチ成立:** 募集した側（プレイヤー1）が、申し込み（プレイヤー2 の署名付き）に応えるマッチイベントを出します。
   部屋 ID とパスワードは暗号化 DM（NIP-17 / NIP-44）で相手にだけ送ります。
5. **結果報告:** 双方が「勝ち／負け／中止」を署名付きで報告します。噛み合う組がそろった時点で確定し、日時を遡らせた報告を後から足しても覆りません。
6. **レート計算:** Glicko-2 で計算します。対戦は報告の締め切りを迎えた時点で1回だけ評価し、成立した時刻の順に処理します。
7. **スナップショット:** 全プレイヤーのレートをまとめた JSON を、GitHub Actions が毎日作って `snapshots/` に置きます。
   クライアントは最新のスナップショットと、それ以降のイベントだけを読みます。選手ページと、ほかのサイト向けの公開 API（[docs/api.md](docs/api.md)）もここから作ります。

### 誰でも検証できる理由

- 対戦・申し込み・報告はすべて、本人の端末が証明書を出した使い捨ての鍵で署名した Nostr イベントです。第三者は作れず、書き換えると署名が合わなくなります。
- 計算は決定的です。同じイベントの集合からはどこで計算しても同じ結果になります（イベントの重複、届く順番、スナップショットの区切り方に左右されません）。
- スナップショットには計算に使ったイベント ID 一覧のハッシュ、前のスナップショットのハッシュ、設定値のハッシュが入っています。
- スナップショットとリレー一覧の取得元は、アプリの設定で差し替えられます。このリポジトリがなくなっても、フォークした先で同じように動きます。

GitHub の履歴は改ざんを「できなくする」ものではなく、「しても分かる」ようにするものとして使っています。

## 対戦ルール（スマブラSP の定義）

今入っている定義はスマブラSP のオンラインのレート戦で広く使われている形式に合わせています。ステージや締め切りなどの値はすべて [`configs/smash_sp.json`](configs/smash_sp.json) にあり、アプリの対戦ルームにも表示されます。
別のゲームで使うときは、同じ形の定義ファイルを足し、アプリが読み込む定義（`apps/web/src/services/config.ts`）とスナップショット生成の `--game` を差し替えます。

- 2本先取。部屋を立てるのは先に待っていたプレイヤーで、部屋 ID とパスワードは対戦相手にだけ届く
- 1戦目: 双方の拒否ステージを除いたステージから各自が選び、ゲーム内の抽選に従う
- 2戦目以降: 直前の敗者が選び、勝者は「おまかせ」。除くのは、勝者が敗者のキャラに設定した拒否ステージだけ
- 拒否ステージ: 相手のキャラごとに設定する。拒否ステージを共有するキャラの組もある
- キャラ変更: 2戦目以降に変えられるのは直前の敗者だけ
- 結果報告には締め切りがある。「未報告」「中止」「食い違ったまま締め切り」の回数を「マナーの目安」として数え、シーズンごとにリセットする。回数の差が大きい相手とはマッチしない

## 既知の限界

次の点は、今の仕組みでは防げていません。

- 鍵と SNS アカウントを用意すれば、捨てアカウント同士で勝ちを偽装できます。短い間に同じ相手と続けた対戦の重みを下げることと、マッチ条件で軽くしているだけです。
- 結果が食い違ったとき、どちらが嘘をついたかは分かりません。双方の回数に数えます。
- X の紐づけは X の埋め込み用の API（oEmbed）で確かめています。X がこの API を止めると、確かめられなくなります。
- 配信される JavaScript がすり替えられると、ページが開いている間は端末の鍵を使われます。鍵そのものは持ち出されず、復活の言葉で取り返せますが、取り消すまでの対戦の結果（最大でおよそ1日分）は残ることがあります。
- GitHub Pages のプロジェクトページ（`<owner>.github.io/<repo>/`）は、同じ owner のほかの Pages サイトと origin が同じです。ほかのサイトの JavaScript から端末の鍵を使える状態になります。公開するときは、独自ドメインか、このアプリ専用のアカウントで配信してください。
- KEL の「先に見た版」を決めるのは、スナップショットを作る人です。誰でも作り直して確かめられますが、ここは中央に寄った部分です。
- まだ知らないアカウントどうしの対戦は、攻撃を受けているときに取りこぼすことがあります。どちらかが既知のアカウントと対戦すれば、以後は取りこぼしません。
- `created_at` は本人が決められる値です。締め切りの判定は完全ではありません。
- 公開リレーはイベントを永久には保持しません。古い対戦の検算は、スナップショットとイベント ID 一覧が頼りです。
- アカウントの公開情報（kind 30756）は置き換え可能なイベントです。更新されると古いバージョンが消え、過去のスナップショットを完全には再計算できなくなります。
- `Math.exp`／`Math.log` の結果は、ブラウザによって末尾のビットが違うことがあります。値を小数第6位で丸めて吸収していますが、まれにずれる可能性は残ります。正とする値はスナップショットです。
- 申込者の待ち時間が切れた直後にマッチが届くと、片方だけが成立したと思う対戦が残ることがあります。双方が報告しなければ、どちらにも数えません。
- 一度送った報告は取り消せず、送り直しても有効なまま残ります。押し間違えた報告に相手が合わせると、その内容で確定します。
- 相手も中止を報告していた場合に限り、中止の報告を日時を遡らせて出し、結果を取り消すことができます。
- 募集や申し込みを大量に出してマッチングを妨げることは、範囲の検査と申し込み件数の上限で軽くしているだけです。

## ローカルで動かす

Node.js 22 以上と Docker が必要です。

```bash
npm install
npm run relay:up                 # ローカルリレーを ws://localhost:7777 で起動
npm run dev                      # Web アプリ（ローカルリレーに接続）
```

ブラウザで表示された URL を2つの別ウィンドウ（片方はシークレットウィンドウ）で開くと、自分同士で対戦を試せます。

```bash
npm test                         # ユニットテスト
npm run typecheck                # 型検査
npm run e2e                      # 2ブラウザの E2E（ローカルリレーが必要）
npm run snapshot -- --cutoff <UNIX秒> [--relays ws://localhost:7777]
npm run site -- --out <出力先> --app-url <アプリの URL>   # 選手ページと公開 API
npm run recovery:build           # 復活の道具（apps/recovery/dist/nostr-rating-recovery.html）
npm run recover                  # 復活の道具の CLI 版
```

自分の GitHub アカウントでアプリを公開する手順は、[docs/self-hosting.md](docs/self-hosting.md) にあります。

| パス | 内容 |
|---|---|
| `packages/core` | UI に依存しない中核ロジック（ゲーム定義、ステージ規則、Glicko-2、イベント、結果確定、マッチング、スナップショット） |

| `docs/protocol.md` | イベントの形式と計算の決まり |
| `docs/adr/` | 設計判断の記録 |
| `docs/self-hosting.md` | 自分でアプリを動かす手順 |
| `docs/api.md` | ほかのサイトからレートを読む公開 API |
